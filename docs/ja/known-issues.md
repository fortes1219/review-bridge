# 既知の問題

## 0.3.0-rc.3 と 0.3.1-rc.3：処理が止まっても「実行中」のまま残る

`start` は、起動したターミナルやエージェントのコマンド実行ツール内で、フォアグラウンドで動作します。そのプロセスが途中で強制終了すると、実際の処理は止まっていても、Bridge の記録では run が実行中のまま残ることがあります。

writer が書き込んだ変更はディスクに残ります。作業が自動でやり直されることはありません。まず `stop <run_id>` で実行を終了し、その後 `resume <run_id>` で再実行してください。**手動で `stop` するまでは、`down` も停止を拒否します。**

### 実行が中断する主なケース

- **エージェントのコマンド実行ツールがタイムアウトする。** Claude Code の Bash ツールは既定で 2 分、最大でも 10 分でコマンドを強制終了します。writer が 2 回作業し、テストも実行すると、それ以上かかることがあります。タイムアウトを長くするか、バックグラウンドで実行して結果ファイルを待ってください。Codex の exec ツールにも独自の時間制限があります。
- **`start` を実行しているターミナルや VS Code のウィンドウを閉じる。** 単一ファイルの `start` で Ctrl+C を押した場合もコマンドは終了しますが、run は続いていることがあります。
- **パソコンのスリープ、シャットダウン、クラッシュ。** Bridge が実行記録を終了する前に、処理が中断することがあります。
- **実行中に新しいバージョンをインストールする。** `npx` はキャッシュ内のプログラムをその場で置き換えます。更新前に作業の完了を待つか、手動で停止してから `npx review-bridge down` を実行してください。

### 復旧手順

プロジェクトのディレクトリで、次の順に実行します。`status` で run ID を確認し、該当する run を停止してから再実行してください。

```sh
npx review-bridge status
npx review-bridge stop <run_id>
npx review-bridge resume <run_id>
```

`<run_id>` は `status` に表示された ID に置き換えます。`resume` は新しい run を作成し、承認カードを表示します。承認してから作業が始まり、中断した処理が自動で再実行されるわけではありません。詳しくは[作業を実行する](./guide/start)を参照してください。

先にバージョンを更新する場合は、`stop` の後に `npx review-bridge down` を実行し、更新後に `resume` してください。`down` 自体は、実行中として残っている run を終了しません。

### 0.3.2 で対応すること

**0.3.2 で、実行プロセスが終了した run の自動検知に対応します。** 0.3.0-rc.3 と 0.3.1-rc.3 のどちらにもまだこの機能はないため、現時点では上の手順で手動復旧してください。

その他の制限は[リリースノート](./release-notes)を参照してください。
